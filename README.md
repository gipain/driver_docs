# driver_docs

Додаток для автоматизації формування первинної документації та звітності
водіїв (ТТН, акт здачі-прийняття робіт), практика 4 курсу.

## Стек

Python, Django 5, PostgreSQL (SQLite - запасний варіант для локальної
розробки без піднятого сервера), WeasyPrint (PDF для акту), openpyxl +
LibreOffice headless (генерація ТТН на основі реального шаблону),
pytest-django + factory_boy (тести й тестові дані).

## Застосунки

| Застосунок | Призначення |
|------------|-------------|
| `core`     | профіль власної компанії |
| `partners` | контрагенти й договори |
| `fleet`    | водії, автомобілі, причепи |
| `trips`    | рейси |
| `documents`| ТТН, акти здачі-прийняття робіт, реєстр і зведені звіти, пакетна генерація |
| `reports`  | порожній каркас застосунку - логіка звітів у підсумку опинилась у `documents`, не винесена в окремий застосунок |

## Передумови

- Python 3.11+
- PostgreSQL 14+ (опційно - без нього проєкт автоматично працює на SQLite)
- **LibreOffice** - потрібен для конвертації заповненої ТТН.xlsx у PDF. Встановлення на Windows через winget:

  ```powershell
  winget install --id TheDocumentFoundation.LibreOffice --silent --accept-package-agreements --accept-source-agreements
  ```

  (звертайте увагу саме на цей `--id`, `LibreOffice.LibreOffice` - неправильний пакет і не встановиться)

- **GTK3 Runtime for Windows** - потрібен для рендеру кирилиці в PDF акту через WeasyPrint. Завантажити зі сторінки релізів [GTK3 Runtime for Windows](https://github.com/tschoonj/GTK-for-Windows-Runtime-Environment-Installer/releases) й встановити. Якщо встановлювач поклав бібліотеки в нестандартну теку (не `C:\Program Files\...`), обов'язково вкажіть реальний шлях у змінній середовища `GTK_RUNTIME_PATH` (див. нижче) - інакше WeasyPrint не знайде DLL і впаде з помилкою імпорту навіть при встановленому GTK.

## Запуск локально

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Скопіюйте `.env.example` у `.env` і заповніть під своє середовище:

```powershell
Copy-Item .env.example .env
```

- `DATABASE_URL` - рядок підключення до PostgreSQL. Без нього (або без файлу `.env` узагалі) проєкт автоматично працює на SQLite (`db.sqlite3`) - для швидкого локального запуску можна нічого тут не міняти.
- `GTK_RUNTIME_PATH` - тека `bin` вашого встановлення GTK3 Runtime (потрібна для PDF акту).
- `SOFFICE_PATH` - шлях до `soffice.exe` (потрібен для PDF ТТН); значення за замовчуванням підходить для типового встановлення LibreOffice через winget.

Далі - міграції, службовий обліковий запис і сервер:

```powershell
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Адмінка: http://127.0.0.1:8000/admin/

## Демонстраційні дані

Команда наповнює базу вигаданими, але реалістичними даними (профіль
компанії, контрагенти, водії, автомобілі, причепи) - зручно для першого
запуску чи підготовки до демонстрації:

```powershell
python manage.py seed_demo_data
```

Кількість записів кожного типу можна змінити прапорцями `--counterparties`,
`--drivers`, `--vehicles`, `--trailers` (за замовчуванням - 6, 8, 5 і 5
відповідно); команду можна запускати повторно, профіль компанії при цьому
не дублюється:

```powershell
python manage.py seed_demo_data --counterparties 10
```

Після цього договори й рейси створюються вручну через UI (`/contracts/new/`,
`/trips/new/`) - саме на цьому шляху (контрагент → авто → договір → рейс →
підтвердження → ТТН → акт) і варто перевіряти застосунок чи готувати
демонстрацію на захисті.

## Основні розділи застосунку

| Розділ | URL |
|---|---|
| Контрагенти / водії / автомобілі / причепи | `/counterparties/`, `/drivers/`, `/vehicles/`, `/trailers/` |
| Договори | `/contracts/` |
| Рейси (створення, підтвердження, формування ТТН) | `/trips/` |
| Акти здачі-прийняття робіт | `/acts/` |
| Реєстр ТТН, зведений звіт і пакетна генерація за період | `/registry/` |
| Адмінка | `/admin/` |

## Тести

Набір написаний у стилі pytest (фікстури, `@pytest.mark.django_db`), тому
запускати його треба саме через pytest, а не `manage.py test` (стандартний
раннер Django такі тести не знаходить):

```powershell
python -m pytest core/ documents/ trips/ partners/ fleet/ -v
```

Набір охоплює перевірку контрольних цифр ЄДРПОУ/ІПН, конвертер чисел у
текст, розрахунок ПДВ (включно з межовими випадками округлення копійки),
усі перевірки готовності рейсу, заповнення ТТН (звірене зі справжнім
зразком), реєстр і зведені звіти, пакетну генерацію з ізоляцією часткових
збоїв.

## Примітка щодо requirements.txt

Файл зафіксовано командою `pip freeze` з робочого віртуального оточення,
тому крім залежностей самого застосунку (Django, openpyxl, WeasyPrint
тощо) у ньому є пакети, потрібні лише для розробки й перевірки під час
практики (`playwright`, `pymupdf`, `matplotlib`, `pywin32`) - для роботи
самого сайту вони не обов'язкові.
